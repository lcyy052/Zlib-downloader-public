# 可靠批量下载：实现要点

这是一份不含个人运行数据的工程说明。使用 Node.js、原生网页和 Playwright，将浏览器会话与文件保存分开；应用是独立非官方工具，只处理用户有权获取的内容。

## 1. 两层状态避免范围混淆

```text
全局 paused
    ├─ 书单 A：source.state = active / paused / cancelled
    ├─ 书单 B：source.state = active / paused / cancelled
    └─ 单本任务：无需书单来源
```

任务只有在全局开启且存在可执行来源时才开始。全局继续不能顺带恢复所有暂停书单，局部继续也不偷偷开启全局。界面根据当前状态生成提示，不能只展示持久化的旧 message。

重启把 running 转为 queued，保留文件与目标目录，等待手动继续。当前不支持字节级续传。

## 2. 网页初始化和文件传输分开限流

网页按钮定位和下载初始化保留串行门，避免抢占页面或会话。文件传输按可配置的总并发 1–3 执行，Chrome 回退另用 TaskLimiter 限制最多 2 路。

许可释放必须等底层清理结束。取消等待任务直接从池中移除，取消活跃任务不能影响邻居；排队等待不计入尚未启动请求的响应超时。

## 3. 可验证的文件落盘

1. 定位可信的同站点文件入口，排除在线阅读。
2. 捕获真实文件响应，优先 Node 流式保存，网络原因再用 Chrome 响应流。
3. 写入唯一临时文件，报告实际字节；拒绝 HTML 错误页并检查长度。
4. 成功后原子落盘，不覆盖同名完整文件；失败或取消清理临时文件。
5. 使用名称、大小和格式签名保守复用已有文件。

签名与长度检查不是原站提供的校验和认证。网站返回的文件内容仍可能有问题，不应把这些检查描述为绝对完整性证明。

## 4. 长书单的结束条件

分页响应正文读取有时间上限。有新书时必须确认 DOM 增长；按钮暂时隐藏或等待超时不是结束证据。显式空中间页按有效游标继续，页码重复则拒绝，避免无限循环。

如果网站标示总数与实际返回数量不同，要同时展示差异和已读结果。不能通过预期书籍数量「补齐」没有返回的内容。

## 5. 重试、代理和取消

HTTP 状态在 Node、Chrome 导航和响应流之间统一保留。临时故障采用有限退避，522 有较长等待；权限/额度问题不会通过无限重试解决。

Node 传输使用当前进程的环境代理或 Windows 手动 HTTP/HTTPS 代理，loopback 绕过代理；不修改系统设置。旧 Node、PAC/SOCKS 不支持时降级。TLS 校验始终保留。

传输等待响应、字节停滞和总时长都有界限，不能因重复无增长进度无限延长存活时间。

## 6. 本地长期运行

后台启动分离父子进程并重定向 stdout/stderr；健康服务可复用。退出 API 保存并暂停任务，关闭网页不等于退出服务。

结构化日志有轮换、内存/队列摘要和退出原因。致命监控只记录，不吞掉默认退出。没有历史日志时不猜测根因；不承诺休眠、关机或强杀后继续运行。

## 7. 测试边界

核心测试验证状态机、文件流、错误分类和持久化。真实 Chrome 的本地 fixture 验证分页、并发隔离、取消和桌面/窄屏页面。它们不证明真实站点当日可用。

网站适配修改还需要经授权的受控真实验证，不能在已有生产下载任务上运行会清理记录的 UI 测试。更多操作边界见 [HANDOFF.md](HANDOFF.md)。
